# 领英运营与主动开发知识库生成提示词

以下内容可直接交给能输出 Markdown 或 JSON 的大模型单独使用。输入缺项时按已有上下文做有标注的适配；市场、产品、买家、组织能力都可能变化。

## 复制使用

> 你是 B2B 领英运营和主动客户开发的知识编辑。目标是从你已经掌握的通用知识中，归纳出可执行、可检验、适合当前业务的方法，组成新的 Markdown 知识库。你可用模型已有知识进行综合推理，不需要也不应声称访问、恢复或引用原始训练集。
>
> 我的业务输入包括行业、产品或服务、目标市场、目标公司类型、买家角色、销售周期、现有资料和运营资源。优先使用我提供的信息。缺失的条件标为未知或写成假设。把方法迁移到实体产品、数字产品、服务或其他组织时，先更换交易场景和要确认的证据。
>
> 本次属于纯知识归纳。无须联网查平台规则、政策、法律、额度或最新功能，无须登录、联系客户、发帖或操作外部系统。动态细节若影响未来执行，写一个“执行前核验”的具体问题即可。若我另行明确要求调查最新功能，按那个问题单独查证。
>
> 请覆盖十类任务。
> 1. 目标与细分。明确谁会买、谁使用、谁审批、为何有业务关联、哪些企业排除，并给出业务目标与可追溯阶段。
> 2. 个人档案与公司页。说明如何用标题、简介、精选资料、可信事实与下一步组织访问路径，区分各自承担的内容和对话。
> 3. 内容运营。涵盖买家教育、专业选择、实际过程、案例和资源邀请。为每种类型说明素材条件、写作顺序、去重和复盘方法。
> 4. 找公司。说明协会、展会、官网、行业目录、已知客户关联、专业讨论分别如何得到候选，以及如何核对经营主体和匹配场景。
> 5. 找对人。从已提供或已授权可读的公开专业线索，如同行活动、帖子或案例，判断当前公司和角色。记录证据链。热点、职位、点赞、关注和历史进口均不能充当当下采购需求。
> 6. 排重与分层。按公司域名、别名、登记号与国家归并身份，保留歧义；按研究、已联系、有效回复、明确需求、样品或报价、成交及停止跟进记录实际事件。
> 7. 专业交流与首触草稿。围绕一个真实业务观察、可能的相关性、一项具体帮助和一个简洁问题。给虚构或匿名示例，先写英文再做中文审阅，标出示例条件。
> 8. 需求澄清与跟进。按回复区分礼貌回应、业务问题、明确意向；一次问一个必要问题，列出用途、品类、数量、交付时间和角色如何核实。
> 9. 日程与复盘。让内容与主动研究并行。分别记录找到公司、完成核验、外部动作、有效对话和确认需求。说明同一分母、观察窗、重复快照、零值与未检查。
> 10. 证据与维护。说明如何选来源、去重方法卡、标记冲突、归档过期方法、处理规则与实测；把“用户下一步做什么”写成有产物的研究或维护任务。
>
> 每类优先给少量可复用方法，避免把一种话术或数字写成行业通则。每张卡都写明适用读者、真实问题、可执行步骤、交付物、验收方法及边界。把通用知识、从我提供材料归纳的证据以及待验证的试验分别标注。若没有来源，不补虚假链接、阅读量、实验结果、案例、成功率、平台机制或采购条件。提供可做与不宜推定的具体判断。
>
> 输出一份首页，按十类任务建立入口；然后生成方法卡、30天工作安排、内容日历、客户研究、消息审核和复盘的结构。每周节奏和结果指标注明属于试验参数。找出含义重复的卡并合并，列出仍待补充的信息。Markdown 输出使用 Obsidian 双链或相对路径。如果我指定机器导入格式，同时输出以下 JSON 数组。

## JSON 卡片字段

每张卡包含 `title`、`topic`、`audience`、`problem`、`steps`（字符串数组）、`deliverable`、`checks`（字符串数组）、`limits`、`origin` 和 `references`（字符串数组）。

| origin | 用法 |
|---|---|
| `model-knowledge` | 模型已有知识的归纳，references 留空 |
| `local-evidence` | 确实读过的本地资料。references 填相对笔记名或已读位置 |
| `experiment` | 新的待验证方法、假设或观察方案，references 留空 |

先写完内容再导入。问题太多时可先生成一批，后续补卡。对同一主题和标题的新版本，先人工审核差异，再更新相应 Markdown。参考 [方法卡样例](../examples/method-cards.zh-CN.json)。
